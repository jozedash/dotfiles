## Verdict

This is a strong branch. It does what most rices never do:

- **one source of truth for colours**, with generated include files instead
  of hand-synced hex values;
- **live reload** for every consumer, without restarting things;
- **fallbacks that warn** instead of breaking (the Adwaita recolouring, a
  missing `colors.lua`, a missing Papirus);
- an **idempotent `setup.sh`** with per-step failure reporting.

Dropping the 33 MB theme dump and `lxappearance` was the right call. The
comments explain *why*, not *what*, and most of the time they're right.

The issues are mostly edge cases and drift. There's one real concurrency
bug, one keybind collision, and idle screen-off that silently doesn't work.

## High

### H1. Concurrent `theme-apply` runs lose updates (verified)

`theme-apply` reads `state.json`, changes it and writes it back with no lock
(`theme-apply:586-590`). Several entry points can overlap: the popup, waybar
right-click (cycle), waybar middle-click (mode) and `Super+Shift+T`. Each one
starts its own process.

In the sandbox, running `--mode light` and `--pair '#00ffff' '#0066ff'`
together **lost one of the two changes 3 times out of 10**.

The same race also hits the GTK theme cleanup. Process A can `rmtree` the
`Hypr-*` theme that process B has just written and pointed GSettings at
(`update_gsettings`, `theme-apply:517-520`).

**Fix** (tested: 0 lost updates out of 10): take an exclusive lock for the
whole run. The lockfile sits next to the state rather than in
`$XDG_RUNTIME_DIR`, so it works the same under `sudo -u` from `link.sh`.
Everything after `parse_args()` in the old `main()` moves into a new
`apply(args)` function, which runs while the lock is held.

```python
import fcntl
...
OUR_GTK_THEME = re.compile(r"Hypr-(dark|light)-[0-9a-f]{8}")
LOCK = theme.STATE_FILE.with_name("lock")
```

```python
def main():
    parser = argparse.ArgumentParser(description=__doc__.split("\n\n")[0])
    ...  # arguments unchanged
    args = parser.parse_args()

    # One run at a time: the popup, waybar's clicks and the keybind can
    # overlap, and each reads, changes and writes the state
    LOCK.parent.mkdir(parents=True, exist_ok=True)
    with open(LOCK, "w") as lock:
        fcntl.flock(lock, fcntl.LOCK_EX)
        apply(args)
```

### H4. hypridle's `dpms` commands fail under the Lua config (verified)

`hypridle.conf` uses the classic dispatcher syntax: `hyprctl dispatch dpms
off` on the 7-minute listener, and `dpms on` for `on-resume` and
`after_sleep_cmd`. With `hyprland.lua` on Hyprland 0.56.2, `hyprctl dispatch`
takes Lua, so the command fails:

```
$ hyprctl dispatch dpms on
error: [string "return hl.dispatch(dpms on)"]:1: ')' expected near 'on'   (rc=7)
```

hypridle ignores the failure, so the screen never turns off when idle. It
stays lit until the 30-minute suspend, which costs battery on a laptop.

**Fix:** use the Lua form. It's what hypridle's own sample
(`/usr/share/hypr/hypridle.conf`) uses, and it works when run live. No other
old-style `hyprctl dispatch` calls are left in the repo; `toggle_layout.sh`
already uses `hl.dsp.*`.

```diff
--- a/.config/hypr/hypridle.conf
+++ b/.config/hypr/hypridle.conf
-    after_sleep_cmd = hyprctl dispatch dpms on  # to avoid having to press a key twice to turn on the display.
+    after_sleep_cmd = hyprctl dispatch 'hl.dsp.dpms({ action = "on" })'  # to avoid having to press a key twice to turn on the display.
@@
-    on-timeout = hyprctl dispatch dpms off                            # screen off when timeout has passed
-    on-resume = hyprctl dispatch dpms on && brightnessctl -r          # screen on when activity is detected after timeout has fired.
+    on-timeout = hyprctl dispatch 'hl.dsp.dpms({ action = "off" })'                   # screen off when timeout has passed
```

### M1. Old GTK themes are deleted even when the GSettings write failed

`update_gsettings` never checks that `gsettings set` worked. It deletes every
other `Hypr-*` theme anyway (`theme-apply:512-520`). Under `link.sh` (run via
`sudo -u` from `setup.sh`) there's no session bus, so:

1. `gsettings get` can still read the old name from the dconf database file;
2. `gsettings set` fails;
3. the theme GSettings still points at gets deleted.

If a session is running at that point (the usual case when re-running
setup), newly started GTK3 apps fall back to unthemed Adwaita until the next
login runs `theme-apply` again.

There's also the opposite case: with no `gsettings` binary at all, the early
`return` means old themes are never cleaned up.

**Fix** (tested with a `gsettings` whose `set` fails: the theme still in use
is kept; when `set` works, the old one is removed): read `gtk-theme` back
after setting, and keep whatever it still names. Cleanup also runs without
`gsettings`.

```python
def update_gsettings(values):
    """Set the GSettings that differ, then delete our GTK themes that are no
    longer in use. Done even with --no-reload: they're settings, not reloads.
    Without a session bus (e.g. under sudo) setting fails; the theme
    GSettings still names is then kept, so apps don't lose it."""
    schema = "org.gnome.desktop.interface"

    def get(key):
        return subprocess.run(["gsettings", "get", schema, key],
                              capture_output=True, text=True).stdout.strip()

    in_use = {values["gtk_theme"]}
    if shutil.which("gsettings"):
        for key, name in GSETTINGS:
            if get(key) != f"'{values[name]}'":
                subprocess.run(["gsettings", "set", schema, key, values[name]], capture_output=True)
        in_use.add(get("gtk-theme").strip("'"))
    if GTK_THEMES.is_dir():
        for old in GTK_THEMES.iterdir():
            if OUR_GTK_THEME.fullmatch(old.name) and old.name not in in_use:
                shutil.rmtree(old)
```

### M7. Version-sensitive coupling

These are the parts most likely to break on a `pacman -Syu`:

| Coupling | Breaks when | Safeguard now | Safeguard with the fix |
|---|---|---|---|
| GTK3 Adwaita resource path and `@define-color theme_*` names (`theme.py:165`, `theme-apply:474`) | GTK 3.24.x rearranges its resources (unlikely, GTK3 is in maintenance) | Warns and falls back to a plain `@import`; MIN_ACCENTS check | Unchanged, already good |
| swaync CSS variable names (`--noti-bg` etc.) and `@import` of `/etc/xdg/swaync/style.css` | swaync renames its variables (it already changed once, in the 0.12 move to GTK4) | None: notifications silently revert to swaync's colours | Checked on every apply; warns with the missing names |
| Hyprland Lua API (`hl.config`, `hyprctl eval`, `hl.dsp.*`) in `hyprland.lua`, `toggle_layout.sh`, `RELOADS` | Hyprland's Lua config is new in 0.5x and still settling | The `pcall(dofile)` fallback covers colours only | A failed reload warns with Hyprland's error |
| `hyprctl hyprpaper wallpaper ', path, cover'` | hyprpaper IPC syntax (changed in 0.8) | Timeout only | A failed reload warns with hyprpaper's error |
| `hypridle.conf` `hyprctl dispatch dpms on/off` | Already broken: classic dispatcher syntax under a Lua config | None | The Lua dispatcher form |
| fastfetch template carries the default module list | fastfetch adds or renames modules | Documented in the template | Unchanged: nothing breaks, you just miss new modules |
| fcitx5 `highlight.svg` not loaded, hence PNG via `resvg` | fcitx5 fixes it (harmless) | n/a | n/a |

**Fix** (tested: a renamed swaync variable is reported, and a clean run is
silent): two checks in `theme-apply`.

1. `reload()` warns (stderr + notification) when a reload command exits
   non-zero. Checked live: `hyprctl eval` exits 7 with the Lua error on a
   bad call, and `hyprctl hyprpaper wallpaper` exits 1 with "bad path". So
   an IPC change in an update shows up on the next theme change.
2. `check_swaync()` takes the variables our `swaync/style.css` overrides
   and warns about any that swaync's own stylesheet no longer contains.

```python
SWAYNC_DEFAULT = Path("/etc/xdg/swaync/style.css")
```

```python
def check_swaync():
    """swaync's style overrides swaync's own CSS variables, which fails
    silently if an update renames them: warn instead."""
    ours = (CONFIG / "swaync/style.css").read_text().split("}")[0]
    names = set(re.findall(r"^\s*(--[\w-]+):", ours, re.M))
    try:
        default = SWAYNC_DEFAULT.read_text()
    except OSError:
        warn(f"swaync: {SWAYNC_DEFAULT} is missing, notifications won't follow the theme")
        return
    missing = sorted(n for n in names if n not in default)
    if missing:
        warn(f"swaync no longer uses {', '.join(missing)}: update ~/.config/swaync/style.css")


def reload(values):
    for name, command in RELOADS:
        if subprocess.run(["pgrep", "-x", name], capture_output=True).returncode != 0:
            continue
        command = [PLACEHOLDER.sub(lambda m: values[m.group(1)], arg) for arg in command]
        if not shutil.which(command[0]):
            continue
        try:
            result = subprocess.run(command, capture_output=True, text=True, timeout=5)
        except subprocess.TimeoutExpired:
            warn(f"{' '.join(command)} timed out")
            continue
        if result.returncode != 0:
            # Most likely the program's IPC changed in an update
            warn(f"reloading {name} failed: {(result.stderr or result.stdout).strip()}")
```

Call it once per run, after `update_gsettings(values)` and before the
reloads:

```python
    if (CONFIG / "swaync").is_dir():
        check_swaync()
```

### L1. `render()` can exit mid-run

`render()` (`theme-apply:414`) exits on an unknown placeholder. By then
`save_state` has run and some files may already be written. Low impact,
since templates are under your control.

**Fix** (tested: a template with `@bogus@` exits with rc 1 and the state
file is byte-identical): render everything first, then save the state, then
write. `update_gtk3_theme` becomes `gtk3_theme`, which returns
`(path, css)` instead of writing it. The `TARGETS` comment that names it
becomes "The GTK3 theme comes from gtk3_theme."

```python
def gtk3_theme(values):

    definitions, then templates/gtk/gtk3.css for what recolouring can't do.
    Sets values["gtk_theme"], its name.
    ...  (rest of the docstring and the body unchanged, except the end:)"""
    ...
    css = render("gtk/gtk3-header.css.in", values) + body
    return GTK_THEMES / values["gtk_theme"] / "gtk-3.0/gtk.css", css
```

```python
def apply(args):
```

### L6. Polling cost on a laptop

`cpu`, `temperature`, `clock` and `custom/powerDraw` all run every second.
The built-in modules don't fork, so they're cheap, and `clock` needs 1 s
for the seconds. `custom/powerDraw` forks bash + cat + jq every second, and
`powerdraw.sh` truncates to whole watts, so anything under 1 W hides the
module.

**Fix:**

```diff
--- a/.config/waybar/config
+++ b/.config/waybar/config
   "custom/powerDraw": {
     "format": "{}",
-    "interval": 1,
+    "interval": 5,
```

`.config/waybar/scripts/powerdraw.sh`:

```bash
#!/usr/bin/env bash
# Battery power draw in watts. Prints nothing (hiding the module) at 0 W, e.g. on
# the charger or on a machine without a battery.

POWER=$(cat /sys/class/power_supply/BAT*/power_now 2>/dev/null | head -1)
[ "${POWER:-0}" -gt 0 ] || exit 0
TEXT=$(awk -v p="$POWER" 'BEGIN { printf "%.1fW", p / 1000000 }')

jq -cn --arg text "$TEXT" '{$text, tooltip: "Power draw \($text)"}'
```

## Against Linux ricing norms

**In line with norms or better:**

- Base16-style role palette with per-format templates. This is the same idea
  as pywal, matugen and wallust, with no extra dependency, and it reloads more
  consumers live than most.
- GTK3 theme in `~/.local/share/themes` instead of `~/.config/gtk-3.0/gtk.css`,
  so waybar and wofi keep priority. Most rices get this wrong.
- `QT_QPA_PLATFORMTHEME=gtk3` instead of qt5ct/qt6ct plus Kvantum: the
  lighter option.
- Papirus symbolic SVGs recoloured, rather than a Nerd Font for the bar.
  Crisper, and no glyph fallback problems with CJK fonts (the comment about
  AR PL fonts stealing the icon codepoints is exactly that problem).
- No AUR. Generated files are gitignored. Per-host overrides live in
  `hosts/<dmi product_version>/`.
- `checkupdates -d` for downloads, which avoids partial upgrades. The
  Arch-news-before-updating prompt is a nice touch.

**Where it departs from the norm:**

- **Session services** are started with `exec_cmd` instead of systemd user
  units under `uwsm`. That's reasonable without `uwsm`, because the units
  need `graphical-session.target`. `uwsm` is the optional upgrade.
- **TLP:** the whole `/etc/tlp.conf` is copied instead of a drop-in in
  `/etc/tlp.d/`. The copy only holds defaults, so it can simply be
  deleted.
- **Wallpapers** live in the repo (4.2 MB of JPEGs). That's common in rices,
  and they're credited (CC BY-SA). Every replacement grows the history
  permanently. No change proposed, but if you start rotating wallpapers,
  move them out of git and add a download step (`curl` from Wikimedia,
  checked by `sha256sum`).

## What's especially good

- `theme.recolour_adwaita`: it reads Adwaita's palette from its own CSS
  instead of hard-coding it, has a measured sanity threshold, and falls back
  safely. Thoughtful, and the docstrings make it maintainable.
- `readable_accent` / `primary_text`: the exact accent for borders and a
  contrast-adjusted one for text. This avoids the usual "pretty but
  unreadable" rice failure.
- Hash-named GTK theme for live restyling: a neat way round GTK3's
  "only reload on name change".
- `toggle_layout.sh`: flock serialisation, hotplug de-duplication,
  enable-before-disable so a black screen can't happen, layouts remembered per
  monitor set.
- `setup.sh`: refuses to install on top of a failed `-Syu`, picks the
  Vulkan provider by GPU instead of letting `--noconfirm` choose, and logs
  every step.
- `hibernate.sh`: checks the filesystem type, regenerates HOOKS from the
  machine's own config, and spots the `systemd` hook case. The
  logind `ProtectHome` drop-in fixes a genuinely obscure problem, and its
  comment explains it.
